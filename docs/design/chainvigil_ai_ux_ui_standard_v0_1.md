## 1. 设计总原则

ChainVigil AI 是 Web3 安全产品，不是交易所、赌场、meme 盘官网或纯 AI 炫技工具。

核心体验原则：

```text
安全感优先。
结论清晰。
证据透明。
不制造恐慌。
不承诺安全。
先查后连。
先读后写。
先报告后执行。
用户永远知道自己在签什么。
所有风险必须有人话解释。
所有检测必须有时间戳。
所有结论必须可复查。
```

## 3. 视觉风格

### 3.1 主视觉方向

建议采用：

```text
深色科技底
高对比卡片
轻微蓝紫 AI 光感
克制风险色
清晰数据卡片
专业报告感
移动端友好
```

可使用类似：

- 深蓝黑背景
- 冷白文本
- 蓝紫渐变点缀
- 低饱和边框
- 卡片式信息层级
- 风险色只在关键元素使用

### 3.2 颜色语义

| 风险等级 | 中文 | 推荐色彩语义 | 使用场景 |
|---|---|---|---|
| BLOCK | 禁买 | 红色 | 明确高危、禁止买入、疑似貔貅 |
| HIGH | 高危 | 橙红 | 多项严重风险 |
| MEDIUM | 谨慎 | 黄色 / 琥珀色 | 有不确定性或中度风险 |
| LOW_TRIAL | 可小额尝试 | 青色 / 蓝绿色 | 未发现致命风险但仍高波动 |
| LOW | 相对低风险 | 绿色 | 未发现明显交易安全风险 |
| UNKNOWN | 无法判断 | 灰色 | 数据不足或仿真失败 |
| AI Insight | AI 信息 | 蓝紫 | AI 总结、解释、建议 |
| VP | 哨点 | 紫金 / 金色 | 积分、等级、贡献 |

### 3.3 色彩使用规则

- 红色只用于真正高危，不要全站大面积红色。
- 绿色不等于“推荐买入”，只表示未发现明显交易安全问题。
- 灰色表示未知，不表示安全。
- VP 色彩要和风险色区分，避免“积分奖励”干扰安全判断。
- 禁买和高危状态要醒目，但不要做恐吓式 UI。

## 4. 字体与排版

### 4.1 字体气质

建议使用现代无衬线字体：

- 中文：思源黑体、阿里巴巴普惠体、苹方类
- 英文：Inter、Geist、Manrope、Satoshi 类

### 4.2 排版原则

- 页面第一屏必须快速给结论。
- 报告页采用清晰层级：结论 > 原因 > 证据 > 详情。
- 技术字段不直接裸露给普通用户。
- 长解释应分段，不堆大段文字。
- 移动端优先考虑单列卡片布局。

### 4.3 字号建议

| 层级 | 使用场景 | 建议 |
|---|---|---|
| H1 | 首页标题、页面主标题 | 大、强对比 |
| H2 | 模块标题 | 明确分区 |
| Body | 普通说明 | 可读性优先 |
| Caption | 时间、来源、辅助说明 | 低对比但可读 |
| Badge | 风险等级 | 简洁醒目 |

## 5. 风险等级表达规范

### 5.1 固定等级

前台统一使用：

```text
禁买
高危
谨慎
可小额尝试
相对低风险
无法判断
```

### 5.2 每个等级必须配解释

#### 禁买

```text
检测到明确重大交易安全风险，不建议买入。
```

#### 高危

```text
检测到多个严重风险，建议谨慎处理，通常不建议买入。
```

#### 谨慎

```text
未发现明确貔貅，但存在不确定性或中度风险，建议小心评估。
```

#### 可小额尝试

```text
未发现致命交易安全问题，但该 token 仍属于高波动链上资产。
```

#### 相对低风险

```text
当前未发现明显交易安全风险，但不代表投资安全。
```

#### 无法判断

```text
当前数据不足或检测失败，无法给出可靠判断。
```

### 5.3 禁用表达

不得出现：

```text
绝对安全
放心买
稳赚
推荐买入
投资价值高
官方认证安全
100% 无风险
```

## 6. 核心组件规范

## 6.1 CA 输入框

### 功能要求

支持：

- 粘贴 CA
- 粘贴 DEX 链接
- 自动识别链
- 手动选择链
- 地址格式校验
- 检测中状态
- 历史检测记录，后续能力
- 快速清空

### 默认文案

```text
粘贴 Token 合约地址或 DexScreener / GMGN 链接
```

### 主按钮

```text
立即 CA 安检
```

### 辅助提示

```text
免费检测｜无需连接钱包｜支持主流 EVM 链
```

### 错误提示

- 地址格式不正确
- 暂不支持该链
- 未识别到 Token 合约
- 数据源暂不可用，请稍后重试
- 请求过于频繁，请稍后再试

## 6.2 风险等级 Badge

### 元素

- 等级文本
- 风险色
- 简短说明 tooltip
- 可选 icon

### 示例

```text
[禁买] 疑似貔貅盘
[高危] LP 未锁 + 可改税
[谨慎] 持仓集中度较高
[无法判断] 仿真失败
```

### 规则

- Badge 文案不超过 6 个中文字。
- 风险等级必须在第一屏可见。
- 同一页面风险色保持一致。

## 6.3 AI 结论卡片

### 结构

```text
标题：AI 结论
风险等级：禁买 / 高危 / 谨慎 / ...
一句话总结
核心原因 3–5 条
操作建议
检测时间
```

### 示例

```text
AI 结论：禁买

该 token 疑似貔貅盘。卖出仿真失败，且合约 owner 可修改卖出税并设置黑名单。

主要原因：
1. 卖出仿真失败
2. 存在黑名单权限
3. Owner 可修改卖出税
4. LP 未锁

建议：不要买入。如果已持有，先尝试小额卖出，不要继续加仓。
```

### 交互规则

- 高危原因默认展开。
- 低风险原因可折叠。
- 检测时间必须可见。
- 重新检测按钮必须清晰。

## 6.4 风险原因卡片

### 字段

- 风险标题
- 严重等级
- 人话解释
- 链上证据
- 是否一票否决
- 数据来源，后续能力

### 错误示例

```text
is_blacklist = true
```

### 正确示例

```text
存在黑名单权限
项目方可能限制指定地址卖出，用户买入后可能无法退出。
```

## 6.5 买卖仿真面板

### 展示字段

- 买入模拟：成功 / 失败 / 无法判断
- 卖出模拟：成功 / 失败 / 无法判断
- 买入税
- 卖出税
- 转账税
- 最大买入限制
- 最大卖出限制
- 仿真路径
- 仿真时间

### 风险表达

卖出失败必须突出显示。

```text
卖出仿真失败：当前检测路径下无法正常卖出，存在买入后无法退出的风险。
```

- Owner 状态

- 是否黑名单

- 是否可暂停交易
- 是否可增发

- 默认展示高危权限。

LP 未锁：项目方可能撤出流动性，导致用户无法正常卖出或价格归零。

### 结构

```text
钱包健康分
高危问题数量
建议立即处理
风险趋势
清理入口
```

### 示例

```text

疑似垃圾资产：38 个

建议优先清理 4 个高危授权。
```

### 规则

- 健康分不是财富分。
- 分数下降时提示原因。
- 不要用恐吓式语言。

## 6.10 授权列表组件

- 资产
- 授权对象
- 授权额度
- 风险等级
- 最近使用
- 风险原因
- 撤销按钮

### 撤销按钮

- 高危授权：主按钮

- 低危授权：弱按钮或更多操作

- 你将撤销哪个 token 的哪个 spender 授权
- 撤销后可能影响什么
- 预计 gas
- 本交易不会转走你的资产
- 取消 / 确认撤销

## 7. 页面级 UX 标准

# 7.1 首页

## 页面目标

让用户在第一屏理解：

```text
这是 ChainVigil AI。
我可以先查 CA。
不需要连接钱包。
```

## 第一屏结构

```text
品牌：ChainVigil AI｜链哨 AI
主标题：买币前，先查 CA。
副标题：AI 检测貔貅盘、高税、黑名单、LP 未锁、Owner 后门、假币与授权风险。
CA 输入框
主按钮：立即 CA 安检
次按钮：检查我的钱包
信任提示：免费检测｜无需连接钱包｜支持主流 EVM 链
```

## 首页不要做

- 不要把 Connect Wallet 作为主 CTA。
- 不要强调平台币。
- 不要做成任务墙。
- 不要放太多技术细节在第一屏。

---

# 7.2 CA 安检页

## 流程

```text
输入 CA
        ↓
自动识别链
        ↓
扫描中，展示阶段
        ↓
输出 AI 结论
        ↓
展示风险详情
        ↓
生成报告链接
        ↓
引导分享 / 钱包体检
```

## 关键要求

- 检测过程要有反馈，避免用户以为卡住。
- 风险结论必须第一屏可见。
- 高危原因默认展开。
- 低风险不说“安全”。
- 未知状态必须清晰说明为什么无法判断。

---

# 7.3 Token 风险报告页

## 第一屏必须包含

- Token 名称
- Chain
- 合约地址
- 风险 Badge
- AI 结论
- 核心风险原因
- 分享按钮
- 重新检测按钮

## 页面内容顺序

```text
结论
原因
证据
详情
下一步
免责声明
```

## CTA 规则

高危：

```text
分享风险报告
举报/补充证据
检查我的钱包
```

低风险：

```text
重新检测
保存报告
检查我的钱包
```

未知：

```text
重新检测
提交人工审核
查看风险说明
```

# 7.4 钱包体检页

## 第一交互

```text
输入钱包地址
```

不是：

```text
Connect Wallet
```

## 页面结构

- 钱包地址输入
- 支持链选择
- 扫描按钮
- 钱包健康分
- 高危授权摘要
- 高危资产摘要
- 粉尘 / 垃圾资产摘要
- 建议操作
- 连接钱包清理 CTA

## 关键要求

- 不连接钱包也能得到基础报告。
- 连接钱包只在执行清理时出现。
- 明确说明只读扫描不会动资产。

- 中危授权列表
- 低危授权列表

## 交互要求

# 8. 状态规范

## 8.1 加载状态

CA 安检加载阶段：

```text
识别合约
检测买卖
扫描权限
检查流动性
分析持仓
生成 AI 报告
```

钱包体检加载阶段：

```text
扫描授权
识别高危资产
分析垃圾资产
计算健康分
生成体检报告
```

## 8.2 空状态

### CA 安检空状态

```text
粘贴 Token 合约地址或 DexScreener / GMGN 链接，开始 CA 安检。
```

### 钱包体检空状态

```text
输入钱包地址，先做一次只读体检。无需连接钱包。
```

### 授权列表空状态

```text
未发现当前链上的活跃授权。你可以切换其他链继续检查。
```

## 8.3 错误状态

错误提示必须包含：

- 发生了什么
- 为什么可能发生
- 用户能做什么

示例：

```text
暂时无法完成卖出仿真。
可能是该 token 没有有效流动性、路由不支持或数据源暂时不可用。你可以稍后重新检测。
```

## 8.4 高危状态

高危状态必须：

- 明确展示风险等级
- 列出主要原因
- 给出保守建议
- 提供分享报告
- 不诱导交易

## 8.5 未知状态

未知状态不得伪装成低风险。

推荐文案：

```text
无法判断：当前数据不足或检测失败，不能确认该 token 是否可正常交易。
```

## 9. 文案规范

### 9.1 语气

- 直接
- 克制
- 专业
- 人话
- 不吓人
- 不装腔

### 9.2 风险文案公式

```text
风险名称 + 这意味着什么 + 用户可能受到什么影响
```

示例：

```text
存在黑名单权限：项目方可能限制指定地址卖出，用户买入后可能无法退出。
```

### 9.3 建议文案

高危：

```text
不建议买入。
```

中危：

```text
建议谨慎评估，不要重仓。
```

低风险：

```text
当前未发现明显交易安全问题，但不代表投资安全。
```

未知：

```text
当前无法给出可靠判断，建议暂缓操作或稍后重新检测。
```

### 9.4 禁用文案

```text
稳赚
必涨
放心买
官方认证安全
100% 安全
马上冲
空投必得
VP 未来换币
```

## 10. 移动端规范

Web3 用户大量来自 Telegram、X 和钱包内置浏览器，因此移动端必须优先。

### 10.1 移动端首页

- 输入框必须在第一屏。
- 主按钮必须明显。
- 不要横向复杂布局。
- 风险结论卡片单列展示。

### 10.2 移动端报告页

第一屏顺序：

```text
风险等级
AI 结论
核心原因
分享按钮
重新检测
```

详情模块可折叠。

### 10.3 移动端授权清理

- 撤销按钮要防误触。
- 确认弹窗必须清晰。
- 交易状态要实时反馈。

## 11. 安全信任设计

### 11.1 首页信任

首页必须强调：

```text
无需连接钱包即可查 CA。
```

### 11.2 钱包连接信任

连接钱包前说明：

```text
连接钱包仅用于读取授权和发起你确认的清理交易。ChainVigil AI 不会保存私钥，也不会自动转走资产。
```

### 11.3 交易确认信任

每次链上交易前必须展示：

- 交易目的
- 交易对象
- gas 预估
- 是否会转移资产
- 用户确认按钮

### 11.4 报告信任

报告中应展示：

- 检测时间
- 数据来源摘要
- 重新检测
- 举报错误
- 免责声明

---

## 12. 可访问性与可读性

- 风险色不能只依赖颜色，必须有文字。
- 深色模式下保证对比度。
- 地址应支持复制和缩略显示。
- 重要按钮不能只用 icon。
- 移动端点击区域足够大。
- 错误信息应明确，不使用晦涩技术错误码。

## 14. Stitch 设计注意事项

给 Stitch 的 Prompt 必须包含：

- 产品名称
- 中文名称
- 口号
- 页面目标
- 用户场景
- 核心 CTA
- 页面模块
- 风险等级语义
- 不要强制连接钱包
- 不要做赌场/meme 风
- 不要承诺安全或收益

不要只说：

```text
Design a Web3 security dashboard.
```

那样会产出泛泛的 UI。

## 15. 总结

ChainVigil AI 的 UX/UI 目标不是“炫酷”，而是让用户在高风险链上场景里快速、冷静、可信地做判断。

核心体验应始终围绕：

```text
看得懂
信得过
不乱签
不误导
可复查
可分享
```
