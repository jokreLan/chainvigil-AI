## 1. 产品总定位

### 1.1 产品一句话

**ChainVigil AI｜链哨 AI 是一个 AI 驱动的 Web3 交易安全与钱包风险管理工具，帮助用户买币前查 CA、识别貔貅和假币，买后体检钱包、清理高危授权和链上隐患。**

### 1.2 核心心智

```text
买前：查 CA，别买错。
交易中：看风险，别签错。
买后：体检钱包，别留隐患。
```

### 1.3 核心口号

```text
买币前，先查 CA。
```

### 1.4 产品关键词

```text
CA 安检
貔貅检测
Token 风险扫描
假币识别
钱包体检
授权清理
资产理发师
哨点 VP
Web3 安全
AI 风险报告
```

### 1.5 产品边界

ChainVigil AI 做的是：

- 交易安全提示
- 风险扫描
- 风险解释
- 钱包健康体检
- 用户确认后的授权清理
- 风险数据沉淀
- 安全贡献与推广积分记录

ChainVigil AI 不做的是：

- 不做投资建议
- 不承诺 token 绝对安全
- 不承诺收益
- 不托管资产
- 不保存私钥
- 不自动帮用户交易
- 不做全自动交易拦截
- V0/V1 不做浏览器插件
- 不承诺哨点 VP 兑换平台币

# 5. 模块 PRD：CA 安检

## 5.1 模块定位

CA 安检是 ChainVigil AI 的最高频入口，服务用户“买币前查 CA”的即时需求。

用户只需要粘贴合约地址或 DEX 链接，系统自动判断该 token 是否存在：

- 貔貅 / Honeypot
- 买得进卖不出
- 高买税 / 高卖税
- 黑名单 / 白名单权限
- Owner 后门
- 可改税
- 可暂停交易
- 可增发
- LP 未锁 / 低流动性
- 持仓过度集中
- 假冒知名币
- 部署者黑历史

## 5.2 用户目标

用户希望在 3 秒到 10 秒内得到一句明确结论：

```text
这个币能不能碰？
为什么？
如果危险，危险在哪里？
下一步应该怎么做？
```

## 5.3 输入方式

支持输入：

- Token 合约地址
- Pair 地址
- DexScreener 链接
- GMGN 链接
- DEXTools 链接
- GeckoTerminal 链接
- 项目官网链接，未来能力
- Telegram 群链接，未来能力

系统自动完成：

- 识别链
- 识别 token address
- 识别 pair address
- 识别 DEX
- 判断是否为 token 合约或 pair 合约

## 5.4 输出结论

前台固定使用以下风险等级：

| 等级 | 中文展示 | 含义 |
|---|---|---|
| BLOCK | 禁买 | 存在明确重大交易安全风险 |
| HIGH | 高危 | 存在多个严重风险，不建议买入 |
| MEDIUM | 谨慎 | 存在不确定性或中度风险 |
| LOW_TRIAL | 可小额尝试 | 未发现致命风险，但仍属于高风险资产 |
| LOW | 相对低风险 | 未发现明显交易安全问题 |
| UNKNOWN | 无法判断 | 数据不足、仿真失败或链暂不支持 |

禁止使用：

- 绝对安全
- 放心买
- 稳赚
- 推荐买入
- 投资价值高

## 5.5 核心检测项

### 5.5.1 买卖仿真

- 是否可以买入
- 是否可以卖出
- 是否疑似 honeypot
- 买入税
- 卖出税
- 转账税
- 最大买入限制
- 最大卖出限制
- 最大钱包限制
- 是否存在冷却时间
- 是否只允许特定地址卖出
- 是否仿真失败

### 5.5.2 合约权限

- 是否开源
- 是否代理合约
- owner 是否放弃
- owner 是否可增发
- owner 是否可暂停交易
- owner 是否可开启/关闭交易
- owner 是否可修改买卖税
- owner 是否可设置黑名单
- owner 是否可设置白名单
- owner 是否可修改最大交易额
- owner 是否可修改最大钱包持仓
- 是否存在隐藏 mint
- 是否存在异常外部调用

### 5.5.3 流动性与 LP

- 是否有流动性池
- 主池在哪个 DEX
- 池子规模
- 配对资产
- LP 是否锁定
- LP 锁定比例
- LP 解锁时间
- LP 是否燃烧
- 项目方是否能撤池
- 最近是否有大额撤流动性
- 买入价格冲击

### 5.5.4 持仓结构

- holder 数量
- 前 10 持仓占比
- 前 50 持仓占比
- deployer 持仓比例
- 合约地址持仓比例
- 黑洞地址占比
- 是否存在狙击机器人集中持仓
- 是否存在关联钱包集群

### 5.5.5 部署者画像

- deployer 创建过多少 token
- 过往 token 是否归零
- 是否存在多次撤 LP 历史
- 是否与已知 scam 地址交互
- 初始资金来源是否异常
- 是否被用户举报
- 是否进入高危部署者库

### 5.5.6 假币识别

- 是否仿冒 USDT / USDC / WETH / PEPE / DOGE 等知名 token
- 名称是否相同或近似
- symbol 是否混淆
- logo 是否盗用
- 官网域名是否相似
- 社媒是否假冒
- 是否存在多个同名 token

## 5.6 一票否决项

出现以下任一项，风险等级直接进入 BLOCK 或 HIGH：

- 卖出失败
- honeypot 命中
- 100% 或接近 100% 卖出税
- 已知恶意合约
- 明确假冒主流 token
- 无有效流动性但诱导购买
- 黑名单功能已命中
- owner 可任意转移用户资产
- 已被人工标记为诈骗

## 5.7 页面流程

```text
用户进入 /check
        ↓
粘贴 CA / DEX 链接
        ↓
系统识别链和 token
        ↓
展示扫描进度
        ↓
输出 AI 结论
        ↓
展示风险详情
        ↓
生成报告链接
        ↓
引导：分享报告 / 检查我的钱包 / 举报纠错
```

## 5.8 状态设计

### 加载状态

扫描阶段展示：

```text
识别合约
检测买卖
扫描权限
检查流动性
分析持仓
生成 AI 报告
```

### 错误状态

- 地址格式错误
- 链不支持
- 未找到合约
- 合约不是 token
- 数据源暂不可用
- 仿真失败
- 请求过于频繁

### 空状态

默认提示：

```text
粘贴 Token 合约地址或 DexScreener / GMGN 链接，开始 CA 安检。
```

## 5.9 成功标准

- 用户 3 步内完成检测
- 结论第一屏可见
- 每个风险点有人话解释
- 每个报告有唯一 URL
- 报告可分享
- 支持重新检测
- 支持举报/纠错

# 6. 模块 PRD：Token 风险报告页

## 6.1 模块定位

Token 风险报告页是 ChainVigil AI 的传播核心、SEO/GEO 核心和用户信任资产。

每次 CA 安检都会生成一个公开报告页：

```text
/token/[chain]/[address]
```

## 6.2 页面目标

第一屏必须回答：

```text
这个币能不能碰？
为什么？
证据是什么？
下一步做什么？
```

## 6.3 页面结构

### 顶部信息区

- Token 名称
- Symbol
- Chain
- 合约地址，可复制
- 风险等级 Badge
- 检测时间
- 重新检测按钮
- 分享按钮

### AI 结论卡片

- 风险等级
- 一句话总结
- 3–5 条核心原因
- 操作建议
- 检测时间

示例：

```text
AI 结论：禁买

该 token 疑似貔貅盘。卖出仿真失败，且合约 owner 可修改卖出税并设置黑名单。

建议：不要买入。如果已持有，先尝试小额卖出，不要继续加仓。
```

### 风险详情区

- 买卖仿真
- 合约权限
- 流动性与 LP
- Holder 分布
- 部署者画像
- 假币风险
- 用户举报
- 历史检测快照

### CTA 区

根据风险等级展示不同 CTA。

高危 token：

- 分享风险报告
- 举报 / 补充证据
- 检查我的钱包

低风险 token：

- 重新检测
- 保存报告
- 检查我的钱包

未知 token：

- 重新检测
- 提交人工审核
- 查看风险说明

## 6.4 分享卡片

报告页必须生成 OG 图，用于 X、Telegram、Discord 分享。

卡片内容：

```text
ChainVigil AI 检测结果：禁买
疑似貔貅盘
卖出失败｜LP 未锁｜Owner 可改税
Token：XXX
Chain：Base
Checked by ChainVigil AI
```

## 6.5 SEO/GEO 规则

并非所有 token 报告页都应被索引。

### 允许 index

- 有交易量
- 有流动性
- 有用户访问
- 有高危标记
- 有独特报告内容
- 热门查询 token
- 被多人举报或分享

### 设置 noindex

- 无流动性
- 无数据
- 重复垃圾 CA
- 错链页面
- 低质量自动页
- 纯空报告

## 6.6 成功标准

- 分享链接打开速度快
- 风险结论第一屏可见
- 社媒卡片清晰
- 用户能一键复查
- 用户能举报误报/漏报
- SEO 页面内容有独特价值

# 7. 模块 PRD：钱包体检

## 7.1 模块定位

钱包体检是从“查币用户”转化为“钱包安全用户”的关键模块。

它帮助用户发现：

- 高危授权
- 无限授权
- 废弃授权
- 高危 token 持仓
- 假币
- 垃圾 Token
- 垃圾 NFT
- 粉尘资产
- 钱包整体健康度

## 7.2 入口

- Token 报告页 CTA：检查我的钱包
- 首页二级入口：钱包体检
- App 控制台
- Telegram Bot 未来入口
- 推广活动页

## 7.3 输入方式

优先支持：

```text
输入钱包地址，只读扫描。
```

高级功能再引导：

```text
连接钱包，执行授权清理。
```

首页和钱包体检入口不得强制连接钱包。

## 7.4 体检内容

### 授权风险

- 授权总数
- 无限授权数量
- 高危 spender
- 中危 spender
- 长期未使用授权
- NFT operator 授权

### 资产风险

- 疑似高危 token
- 疑似假币
- 垃圾 Token
- 垃圾 NFT
- 粉尘资产
- 无流动性资产

### 交互风险

- 最近是否与高危合约交互
- 是否授权过已知钓鱼合约
- 是否持有高危部署者发行的 token

## 7.5 钱包健康分

钱包健康分范围：0–100。

建议维度：

```text
高危授权数量
无限授权数量
高危资产持仓
垃圾资产数量
最近高危交互
授权资产价值暴露
钱包整洁度
```

展示示例：

```text
钱包健康分：62 / 100
高危授权：4 个
无限授权：17 个
疑似垃圾资产：38 个
建议优先清理 4 个高危授权。
```

## 7.6 用户路径

```text
用户输入钱包地址
        ↓
只读扫描
        ↓
展示钱包健康报告
        ↓
发现高危授权
        ↓
引导连接钱包
        ↓
进入授权清理
        ↓
撤销后生成清理报告
        ↓
获得哨点 VP
```

## 7.7 成功标准

- 不连接钱包也能看到基础报告
- 风险项清晰解释
- 高危问题优先级明确
- 能自然导向授权清理
- 不制造不必要恐慌

# 8. 模块 PRD：授权扫描与授权清理

## 8.1 模块定位

授权扫描与清理是 ChainVigil AI 的核心安全功能之一，解决用户长期积累的历史授权隐患。

## 8.2 支持范围

优先支持 EVM：

- ERC20 `approve(spender, amount)`
- ERC721 `setApprovalForAll(operator, true/false)`
- ERC1155 `setApprovalForAll(operator, true/false)`
- 无限授权
- 高危 spender
- 长期未使用授权

未来支持：

- Permit / Permit2 风险识别
- 更多链授权模型
- 智能账户批量操作

## 8.3 授权风险分级

### 高危

- 未知 spender
- 已标记恶意 spender
- 钓鱼 / 跑路项目合约
- 无限授权 + 长期未使用
- 高价值资产授权给未知合约
- 被用户举报且人工确认

### 中危

- 长期不用
- 废弃 DApp
- 过期空投合约
- 低活跃项目
- 用户已无相关资产但授权仍存在

### 低危

- 知名协议
- 用户近期仍使用
- 授权限额较低
- 风险数据源无异常

## 8.4 授权列表字段

每一行授权应展示：

- 资产名称
- Token 合约地址
- Spender / Operator
- 授权额度
- 是否无限授权
- 授权类型
- 风险等级
- 风险原因
- 最近使用时间，若可得
- 撤销按钮

## 8.5 撤销流程

```text
用户选择授权项
        ↓
点击撤销
        ↓
确认弹窗展示交易含义
        ↓
显示 gas 预估
        ↓
用户确认
        ↓
钱包签名
        ↓
链上执行
        ↓
刷新状态
        ↓
生成清理报告
```

## 8.6 撤销确认弹窗必须展示

- 撤销哪个 token 的授权
- 撤销哪个 spender/operator
- 撤销后可能影响什么
- 预计 gas
- 交易不会转走用户资产
- 用户可取消

## 8.7 安全原则

- 用户自己确认
- 用户自己签名
- 不隐藏 calldata
- 不代签名
- 不托管资产
- 不请求用户把 token 授权给 ChainVigil AI
- 不自动批量执行
- 批量撤销也要逐项可审计

# 9. 模块 PRD：资产理发师

## 9.1 模块定位

资产理发师是买后清理模块，偏“事后清理、资产规整、风险根治”。

它与 CA 安检严格区分：

```text
CA 安检：买前判断，别买错。
资产理发师：买后清理，别留隐患。
```

## 9.2 核心功能

- 授权深度清理
- 粉尘资产扫描
- 垃圾 Token 识别
- 垃圾 NFT 识别
- 低价值资产分类
- 不建议处理资产标记
- 可回收资产估算
- 钱包整洁度评分
- 资产规整报告

## 9.3 粉尘资产分类

### 可回收资产

- 有价格
- 有流动性
- 可正常卖出
- 手续费低于回收价值
- 无高危交互风险

### 建议隐藏资产

- 无价格
- 无流动性
- spam token
- 垃圾 NFT
- 无效空投

### 禁止处理资产

- 疑似 honeypot
- 交互可能触发风险
- 高税/黑名单 token
- 身份类 NFT / SBT
- 历史凭证类资产
- 无法判断风险的资产

## 9.4 当前阶段边界

V0/V1/V2/V3 早期只做：

```text
扫描
分类
建议
报告
```

暂缓：

```text
自动 swap
跨链归集
自动 bridge
自动 burn NFT
自动动资产
```

## 9.5 核心保护机制

任何粉尘处理建议都必须满足：

```text
预计收益 > gas + 滑点 + 路由费 + 风险成本
```

否则应显示：

```text
不建议处理，避免倒贴 gas 或触发风险。
```

# 10. 模块 PRD：哨点 VP 积分体系

## 10.1 积分命名

```text
中文名称：哨点
英文名称：Vigil Points
简称：VP
```

## 10.2 积分定位

哨点是用户在 ChainVigil AI 生态中的成长、贡献和推广记录。

哨点用于：

- 用户等级
- 产品权益
- 高级检测额度
- Bot 权益
- 风险报告额度
- 榜单身份
- 活动资格
- 未来生态激励参考

重要边界：

```text
哨点不是 token。
哨点不可交易。
哨点不承诺兑换平台币。
哨点不承诺固定比例。
```

## 10.3 前台展示

前台统一展示：

```text
我的哨点：12,450 VP
```

后台拆分三类：

- 成长哨点
- 贡献哨点
- 推广哨点

## 10.4 成长哨点

获得方式：

- 每日 CA 安检
- 完成钱包体检
- 查看风险报告
- 使用 Telegram Bot
- 完成基础任务

作用：

- 等级
- 额度
- 活跃记录
- 产品权益

## 10.5 贡献哨点

获得方式：

- 首个发现高危 CA
- 举报假币
- 提交钓鱼地址
- 验证高危授权
- 提交风险规则
- 修正误报/漏报

作用：

- 安全猎人身份
- 贡献榜
- 未来生态激励参考

## 10.6 推广哨点

获得方式：

- 分享报告带来有效检测
- 邀请用户完成钱包体检
- 邀请 Bot 进入真实群
- KOL 内容带来有效转化
- 群主带来真实群内检测

作用：

- 推广榜
- 渠道权益
- Bot 权益
- 活动资格

## 10.7 结算原则

```text
奖励有效行为，不奖励空动作。
低价值行为即时结算。
高价值行为延迟确认。
疑似刷分进入待审核。
恶意行为清零或封禁。
```

## 10.8 禁止设计

不要出现：

- 100 VP = 1 token
- 哨点未来必定空投
- 做任务赚平台币
- 充值越多 VP 越多
- 邀请钱包直接高额给分
