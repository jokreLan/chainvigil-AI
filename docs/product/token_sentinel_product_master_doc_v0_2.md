**文档状态：产品共识定稿版，用于后续版本规划。**  
**更新日期：2026-07-08**  
**核心定位：买前查 CA、交易中看懂风险、买后清理隐患。**

## 0. 本版最新确认

本版合并了最近讨论后的关键决策：

- **主产品形态：Web DApp。** 但第一入口不是 Connect Wallet，而是免费 CA 安检和只读钱包体检。
- **暂不做全自动交易拦截。** Web DApp 不负责拦截所有钱包签名，也不做强制交易阻断。
- **浏览器插件不进入 V0/V1 核心范围。** 插件从核心模块降级为 P3 之后可选增长工具，未来最多做“交易页面风险提示”，不做自动拦截、不代签、不执行交易。
- **核心增长组合：Web DApp + Telegram Bot + 分享报告 + SEO/GEO + 积分推广。**
- **积分体系承担三种作用：用户留存、安全贡献记录、推广奖励。** 积分可服务未来平台币准备，但不公开承诺兑换比例，不把积分直接包装成未来平台币。

一句话定稿：

> 先做一个 Web3 安全工具站，用“买币前先查 CA”吃流量，用报告页和 Telegram Bot 做传播，用钱包体检和授权清理做转化，用积分体系驱动留存、贡献和推广。

## 1. 产品总定位

### 1.1 产品一句话

**Token 哨兵 / 资产理发师是一套面向 Web3 用户的钱包安全与资产清理系统，帮助用户在买币前识别高危合约、在交易前看懂风险、在买后清理历史授权和粉尘资产。**

### 1.2 核心用户心智

| 场景 | 用户问题 | 产品回答 |
|---|---|---|
| 买前 | 这个 CA 能不能买？是不是貔貅？ | Token 哨兵：买前验币，先查 CA |
| 交易中 | 这次授权/签名/交易有没有坑？ | AI 防诈哨兵：解释风险，辅助判断 |
| 买后 | 钱包里旧授权、粉尘、垃圾 NFT 太乱怎么办？ | 资产理发师：清旧风险，归整资产 |
| 社群传播 | 群里有人发 CA，我想快速判断 | Telegram Bot：群内一键安检 |
| 长期激励 | 用户为什么持续使用和传播？ | 哨兵积分：留存、贡献、推广奖励 |

### 1.3 三段式产品闭环

```text
买前：CA 安检 → 判断能不能买、能不能卖、是否高危
交易中：风险解释 → 帮用户看懂授权、签名、合约与路径风险
买后：钱包体检 → 授权清理、粉尘扫描、资产规整、风险复查
```

### 1.4 产品边界

产品不做投资建议，不承诺某个币“值得买”。产品输出的是**交易安全风险判断**，不是价格判断、收益预测或投资评级。

正确表达：

> 未发现明显交易安全问题，但仍存在价格波动、项目方作恶、流动性变化等风险。

避免表达：

> 这个币安全，可以放心买。  
> 这个币一定会涨。  
> 这个项目没有任何风险。

### 2.2 模块之间的关系

```text
Telegram / X / SEO / GEO / KOL / 社群
                ↓
        免费 CA 安检 Web DApp
                ↓
        Token 风险报告页 / 分享卡片
                ↓
       钱包只读体检 / 风险健康分
                ↓
       连接钱包执行授权清理 / 粉尘扫描
                ↓
       会员转化 / 积分激励 / 长期监控
```

### 2.3 为什么不把浏览器插件作为核心

浏览器插件原本最大的价值是交易现场提示和自动拦截。但本项目当前明确不做全自动交易拦截，因此插件的核心价值下降。早期做插件会带来额外维护成本、权限信任成本、Chrome 审核成本、站点适配成本和移动端覆盖不足问题。

本版决策：

- V0/V1 不做浏览器插件。
- 插件不作为核心产品形态。
- 后续如数据验证用户强需求，可做轻量“交易页面风险提示插件”。
- 即使未来做插件，也不做代签、不做资产执行、不做强制交易拦截。

## 3. 用户痛点与目标用户

### 3.1 高频痛点

Web3 长期用户、多链用户、meme 用户、撸毛用户、DeFi 用户普遍存在以下问题：

- 群里、X 上、KOL 发了一个 CA，不知道这个币能不能买。
- 买进去之后才发现卖不出，或者卖出税极高。
- 分不清真假 USDT、假 PEPE、假热门币、仿盘合约。
- 看不懂合约里的 owner 权限、黑名单、白名单、可改税、可暂停交易等风险。
- 钱包里堆积大量历史授权，尤其是无限授权和废弃 DApp 授权。
- 多链地址里有大量 1U、0.5U、0.1U 的粉尘资产、垃圾 NFT 和无效空投。
- 一条链一条链检查、一个授权一个授权撤销，手动成本极高。

| 用户类型 | 主要需求 | 付费/传播潜力 |

| 多链 DeFi 用户 | 授权清理、钱包体检 | 高付费，中传播 |
| 撸毛 / 空投用户 | 多链资产规整、粉尘扫描、假空投识别 | 高传播，中付费 |
| NFT 用户 | 垃圾 NFT、授权、假空投识别 | 中传播，中付费 |
| 群主 / KOL | 群内 CA 检测、风险背书、推广奖励 | 高传播 |
| 开发者 / 工具方 | Token 风险 API、数据集成 | 中传播，高战略价值 |

### 3.3 核心用户心智口号

中文主口号：

> 买币前，先查 CA。

英文主口号：

> Check the contract before you buy.

安全工具口号：

> 不替你投资，只帮你避坑。

## 4. Web DApp 产品形态

### 4.1 总体原则

Web DApp 是主产品形态，但不是传统“打开就连接钱包”的 DApp。它应该先是一个安全工具站，再逐步进入链上执行。

核心体验顺序：

```text
不登录 → 不连接钱包 → 输入 CA 或钱包地址 → 免费查看只读报告 → 用户信任后再连接钱包执行操作
```

### 4.2 前台公开工具区

不需要连接钱包，承担获客、传播、SEO/GEO 和信任建立。

功能包括：

- CA 安检工具。
- Token 风险报告页。
- 钱包地址只读体检。
- 高危 CA 数据库。
- 假币数据库。
- 风险百科与避坑教程。
- 每周高危榜单。
- 分享报告卡片。
- Telegram Bot 落地页。

### 4.3 钱包连接 DApp 区

用户已经建立信任后，连接钱包执行安全操作。

功能包括：

- 授权扫描。
- 高危授权撤销。
- 批量撤销。
- 粉尘资产扫描。
- 粉尘归集，后置。
- 垃圾 NFT 标记/隐藏建议。
- 风险监控。
- 会员权益。
- 积分中心和推广中心。

## 5. Token 哨兵：CA 买前安检

### 5.1 模块定位

CA 买前安检是最高频入口，也是产品传播的第一抓手。用户输入 token 合约地址、DEX 链接、pair 地址或项目链接，系统自动识别链和合约，输出交易安全结论。

### 5.2 用户输入

支持输入：

- Token 合约地址。
- DexScreener / GMGN / DEXTools 链接。
- Pair 地址。
- 项目官网链接。
- X / Telegram 项目链接，后续支持。
- 钱包 swap 页面复制出来的 token 地址，后续支持。

### 5.3 检测维度

| 维度 | 检测内容 |
|---|---|
| 基础信息 | 链、名称、symbol、decimals、合约类型、创建时间 |
| 买卖仿真 | 能否买、能否卖、买税、卖税、滑点、到账异常 |
| 合约权限 | owner、是否可改税、黑名单、白名单、暂停交易、增发、销毁 |
| 流动性 | 池子规模、DEX、LP 是否锁定/燃烧、价格冲击、撤池风险 |
| 持仓分布 | holder 数、前 10/50 持仓、部署者持仓、关联地址集中度 |
| 部署者历史 | 是否多次发盘、是否有归零币、是否有撤池/黑名单历史 |
| 假币识别 | 是否冒充 USDT/USDC/WETH/PEPE 等知名币 |
| 外部风险 | 是否命中黑名单、社区举报、安全数据源标记 |

### 5.4 风险结论分级

| 等级 | 说明 | 产品表达 |
|---|---|---|
| 禁买 | 存在明确高危，如卖不出、疑似貔貅、假币、黑名单命中 | 建议不要买入 |
| 谨慎 | 没有一票否决，但存在高税、LP 未锁、owner 权限过高等 | 仅适合极小额试探 |
| 可小额尝试 | 未发现明显致命风险，但仍是高波动新资产 | 不建议重仓 |
| 相对低风险 | 多项安全检测正常，流动性和权限相对健康 | 仍不构成投资建议 |
| 无法判断 | 数据不足、仿真失败、链/DEX 不支持 | 建议不要贸然交易 |

### 5.5 一票否决项

以下情况直接触发“禁买”或“无法判断，不建议交易”：

- 买得进卖不出。
- 卖出税接近或等于 100%。
- 明确 honeypot / 貔貅特征。
- 合约命中已知恶意库。
- 假冒主流 token。
- 无有效流动性但诱导购买。
- 仿真失败且存在 owner 高危权限。
- 项目方可随时拉黑、暂停交易或任意修改税率，且无可信约束。

### 5.6 报告页第一屏

报告页第一屏必须极简、直接、人话化。

示例：

> AI 结论：禁买｜疑似貔貅盘  
> 原因 1：卖出仿真失败，当前路径无法正常卖出。  
> 原因 2：合约 owner 可修改卖出税。  
> 原因 3：存在黑名单权限，项目方可限制指定地址卖出。  
> 原因 4：LP 未锁，存在撤池风险。  
> 建议：不要买入。如已持有，先尝试小额卖出，不要继续加仓。

## 6. AI 防诈哨兵

### 6.1 模块定位

AI 防诈哨兵负责事前/事中的风险解释，核心是“让用户看懂风险”，而不是替用户自动拦截所有交易。

本版确认：

- 不做全自动交易拦截。
- 不承诺拦截所有钱包签名。
- 不做浏览器插件强拦截。
- 以 Web DApp、报告页、Bot 提醒、交易解释为主。

### 6.2 能力范围

| 能力 | 当前定位 |
|---|---|
| CA 安检 | P0 核心入口 |
| 授权风险解释 | P1，与授权清理结合 |
| 钱包地址风险识别 | P1，体检报告中展示 |
| 钓鱼网址识别 | P2，可作为扩展 |
| 签名内容解释 | P2/P3，后续做，不作为首发核心 |
| 自动交易拦截 | 不做 |
| 浏览器插件拦截 | 不做，后续可选提示插件 |

### 6.3 产品表达原则

AI 不是“替用户投资”，而是：

- 把复杂合约字段翻译成人话。
- 把链上证据整理成结论。
- 标出高危操作的原因。
- 给出建议但保留用户最终决策。

## 7. 资产理发师：买后清理与资产规整

### 7.1 模块定位

资产理发师属于“事后清理、资产规整、风险根治”模块。它与 AI 防诈哨兵严格区分：

| 模块 | 场景 | 用户心智 |
|---|---|---|
| AI 防诈哨兵 | 买前/交易中 | 别被骗、别买错、别签错 |
| 资产理发师 | 买后/存量 | 不乱、不脏、不留隐患、资产归整 |

### 7.2 授权深度清理系统

目标：清除用户钱包中的历史授权风险。

核心功能：

- 多链授权扫描。
- 展示已授权合约、spender、额度、授权类型、授权风险。
- AI 风险分级：高危、中危、低危。
- 单个撤销。
- 批量撤销，会员能力。
- 授权清理报告。

风险分级逻辑：

| 等级 | 典型情况 |
|---|---|
| 高危 | 未知 spender、疑似钓鱼、无限授权、已跑路/被攻击项目、可疑 Permit/Permit2 授权 |
| 中危 | 长期不用、过期 DApp、废弃空投合约、低信誉协议 |
| 低危 | 常用正规协议、用户近期仍在使用、风险较低 spender |

执行原则：

- 所有撤销必须用户确认。
- 撤销前展示交易内容和 gas 预估。
- 不自动替用户撤销。
- 不托管资产、不代管私钥。

### 7.3 粉尘资产智能扫描

目标：帮助用户识别钱包里的零散资产、垃圾 token、无效 NFT 和可回收小额价值。

粉尘分类：

| 类型 | 处理建议 |
|---|---|
| 可归集资产 | 有价格、有流动性、可卖、收益大于成本，可进入归集候选 |
| 建议隐藏资产 | 无价格、无流动性、spam token、垃圾 NFT，建议隐藏或标记 |
| 禁止处理资产 | honeypot、高税、恶意 token、身份类 NFT/SBT、交互风险高资产 |

### 7.4 粉尘归集

粉尘归集是高付费意愿功能，但执行复杂，后置开发。

归集前必须判断：

```text
回收价值 > gas + 路由费 + 滑点 + bridge fee + 风险成本
```

保护机制：

- 不划算则禁止归集。
- 高危币不归集。
- 无流动性资产不归集。
- 需要恶意授权的资产不归集。
- 默认先扫描，不默认执行。
- 执行前让用户确认每一步。

## 8. 钱包健康报告

### 8.1 报告目标

钱包健康报告是连接“CA 安检用户”和“资产清理用户”的转化桥梁。

用户查完 CA 后，引导：

> 你刚刚查了这个币，要不要顺便检查你的钱包里是否还有高危授权、垃圾资产和历史隐患？

### 8.2 只读体检

用户可输入钱包地址，不连接钱包即可查看：

- 钱包健康分。
- 持有高危 token 数量。
- 疑似垃圾 NFT 数量。
- 历史授权数量。
- 无限授权数量。
- 高危授权数量。
- 粉尘资产估算。
- 推荐清理动作。

### 8.3 连接钱包后的能力

连接钱包后可执行：

- 单个撤销。
- 批量撤销。
- 授权清理报告生成。
- 粉尘扫描深度版。
- 会员权益激活。

### 8.4 分享卡片

钱包健康报告可以生成分享卡片：

> 我的钱包健康分：72  
> 高危授权：3 个  
> 无限授权：11 个  
> 粉尘资产：$42  
> 垃圾 NFT：17 个  
> Scan by Token 哨兵

分享卡片是传播素材，但默认隐藏完整钱包地址，保护用户隐私。

### 9.1 总体传播公式

```text
积分体系驱动推广和留存
```

### 9.2 SEO 页面矩阵

| 页面类型 | 作用 | 示例 |
|---|---|---|
| 工具页 | 吃高意图搜索 | honeypot checker、token scanner、CA 安检 |
| 单币报告页 | 程序化 SEO 和分享 | `/token/base/0x...` |
| 风险百科页 | GEO/AEO 引用 | 什么是貔貅、什么是黑名单、什么是 LP 未锁 |
| 高危数据库 | 权威数据资产 | 高危 CA、假 USDT、部署者黑名单 |
| 对比页 | 吃竞品搜索 | Token scanner alternative、honeypot checker 对比 |
| 榜单页 | 社交传播和周期内容 | 本周十大高危 CA、本周假币榜 |

### 9.3 GEO 方向

目标不是简单排名，而是成为 AI 搜索会引用的 Web3 安全数据源。

关键动作：

- 输出结构化风险百科。
- 输出可引用的高危 CA 数据库。
- 输出每周/月安全报告。
- 开放 API 文档和开发者资源。
- 让品牌词与 token scanner、honeypot checker、wallet approval checker、Web3 security tool 绑定。

### 9.4 Telegram Bot

Telegram Bot 是早期最重要的社群流量入口。

基础能力：

- `/check 0x...` 查询 CA 风险。
- 群内识别 CA，返回简版风险结论。
- 高危 token 自动提示，需群主开启。
- 返回完整报告页链接。
- 记录推广归因和群组贡献。

群主价值：

> 帮群主降低群内土狗诈骗和假 CA 风险，让群变得更可信。

### 9.5 分享卡片

每次 CA 安检和钱包体检都应该生成可传播卡片。

卡片原则：

- 第一眼看到结论。
- 高危原因不超过 4 条。
- 有检测时间和链。
- 有报告链接。
- 支持中文/英文版本。
- 可以带推广码和贡献者署名。

### 9.6 KOL / 群主推广

推广不奖励“发一条内容”本身，而奖励带来的有效行为：

- 有效访问。
- CA 检测。
- 钱包体检。
- 授权清理。
- Bot 入群。
- 会员转化。

推广关系需要清晰披露，避免误导用户。不能承诺“推广积分必然换平台币”。

## 10. 积分体系：留存、贡献与推广奖励

### 10.1 积分体系定位

积分体系承担三种作用：

```text
1. 留存：让用户持续使用产品
2. 贡献：记录真实安全贡献
3. 推广：奖励带来真实增长的人
```

建议命名：

> 哨兵积分 / Sentinel Points

正式定义：

> 哨兵积分是用户在 Token 哨兵生态中的产品使用、安全贡献、社区传播和推广行为的非转让积分，用于等级、权益、任务解锁、贡献记录和未来生态激励参考。

### 10.2 三类积分来源

| 类型 | 作用 | 示例行为 |
|---|---|---|
| XP 成长积分 | 活跃、等级、产品权益 | 查 CA、完成体检、连续使用 |
| 安全贡献分 | 真实安全网络贡献 | 举报高危 CA、发现假币、贡献规则 |
| 推广奖励分 | 增长和渠道奖励 | 分享报告带来检测、Bot 入群、KOL 转化 |

前台可以统一显示“哨兵积分”，后台必须区分积分来源。

### 10.3 推广奖励原则

推广积分的核心原则：

> 奖励结果，不奖励动作。

不要单纯奖励：

- 分享一下。
- 邀请一个空钱包。
- 转发一条推文。
- 连接一次钱包。

应该奖励：

- 分享带来有效访问。
- 邀请带来 CA 检测。
- 邀请带来钱包体检。
- 群主安装 Bot 并产生活跃检测。
- KOL 内容带来真实转化。
- 开发者集成 API 并产生活跃调用。

### 10.4 推广漏斗奖励

| 转化行为 | 推广价值 |
|---|---:|
| 有效访问 | 低 |
| 首次 CA 检测 | 中 |
| 首次钱包体检 | 中高 |
| 连接钱包完成授权扫描 | 高 |
| 撤销高危授权 | 很高 |
| 安装 Bot 到真实群 | 很高 |
| 付费会员 | 很高 |
| API / 工具集成 | 战略级 |

### 10.5 积分权益

积分短期必须有实际用途，不能只靠未来平台币预期。

可兑换权益：

- 高级 CA 检测次数。
- 深度合约报告。
- 钱包体检额度。
- 授权批量清理折扣。
- 粉尘扫描额度。
- Telegram Bot 群额度。
- API 调用额度。
- 高危监控地址数。
- 风险猎人徽章。
- 群主认证。
- 内测资格。
- 榜单展示。

### 10.6 Season 赛季制

积分采用赛季制，便于运营、快照、反作弊和规则调整。

示例：

| 赛季 | 目标 |
|---|---|
| Season 0：创世哨兵 | 种子用户、KOL、群主、安全猎人 |
| Season 1：买前安检赛季 | 推广“买币前先查 CA”心智 |
| Season 2：钱包健康赛季 | 推动钱包体检和授权清理 |
| Season 3：安全网络赛季 | 建立高危 CA、假币、部署者风险数据库 |

### 10.7 反女巫与反作弊

必须从第一天开始做反作弊。

高风险行为：

- 自己邀请自己。
- 批量钱包注册。
- 批量查垃圾 CA。
- 脚本刷访问。
- 假群安装 Bot。
- 自建垃圾合约再举报。
- KOL 假流量。
- 多地址互刷积分。

保护机制：

- 待确认积分。
- 延迟结算。
- 每日上限。
- 质量系数。
- 可信度系数。
- 反女巫系数。
- 设备/IP/钱包聚类。
- 高价值贡献人工审核。

### 10.8 与未来平台币的关系

积分可以为未来平台币做准备，但对外必须保持边界。

可以说：

> 积分用于记录你对生态的活跃度、安全贡献和推广贡献。未来如有生态激励、治理权益或平台代币计划，积分和贡献记录可能作为参考因素之一，具体规则以未来公告为准。

不能说：

> 100 积分 = 1 token。  
> 现在刷积分，未来必定空投。  
> 邀请越多，未来币越多。  
> 付费会员保证拿币。

内部建议未来权重：

| 维度 | 建议权重 |
|---|---:|
| 安全贡献 | 40% |
| 真实产品使用 | 25% |
| 推广贡献 | 20% |
| 生态/开发者贡献 | 10% |
| 早期身份 | 5% |

推广重要，但不能压过安全贡献。产品本质是安全网络，不是邀请返佣平台。

## 13. 技术难点与卡点

### 13.1 风险判断准确率

误报太多，用户不信；漏报高危，用户受损。解决方式是多源交叉验证、风险分级、一票否决、证据展示、复查机制和用户反馈闭环。

### 13.2 动态合约风险

一个币现在能卖，不代表未来还能卖。owner 改税、拉黑、暂停交易、撤 LP 都可能发生。报告必须展示检测时间，并支持重新检测和持仓监控。

### 13.3 交易仿真覆盖

不同链、DEX、router、launchpad 模型不同，仿真不可能一开始全覆盖。V0 应优先覆盖主流 EVM 链和主流 DEX 模型，无法判断时明确输出“无法判断”。

### 13.4 授权数据完整性

完整授权扫描需要索引 Approval、ApprovalForAll、Permit/Permit2 等多种授权类型。早期可接第三方 API，后续逐步自建授权事件索引。

### 13.5 粉尘归集执行风险

粉尘归集涉及 swap、bridge、gas、滑点、恶意币和授权风险，必须后置。第一阶段先做扫描和估算，执行归集必须极其保守。

### 13.6 积分反作弊

积分一旦用于推广和未来生态激励，就必然被刷。必须从第一天设计待确认积分、延迟结算、反女巫系数、质量系数和人工审核。

## 14. 安全、信任与合规边界

### 14.1 安全边界

产品必须坚持：

- 不托管资产。
- 不代管私钥。
- 不要求用户导入助记词。
- 不默认连接钱包。
- 不自动执行资产操作。
- 所有链上执行都要用户确认。
- 执行前解释交易意图和风险。
- 高危或无法判断时宁可保守提示。

### 14.2 合规表达边界

避免：

- 投资建议。
- 收益承诺。
- 保证安全。
- 保证空投。
- 积分固定兑换平台币。
- 付费会员保证未来 token。

推荐表达：

- 交易安全风险检测。
- 不构成投资建议。
- 检测结果基于当前链上状态。
- 未来风险可能变化。
- 积分用于产品权益和生态贡献记录。

### 14.3 隐私边界

- 钱包报告分享默认隐藏完整地址。
- 推广归因不公开用户敏感数据。
- Bot 群数据仅用于风险检测、频控和贡献统计。
- 用户可选择不公开个人榜单昵称。

## 18. 最终定稿总结

产品主线：

```text
买前查 CA → 生成风险报告 → 分享传播 → 钱包体检 → 授权清理 → 积分留存和推广 → 未来安全网络与平台币基础
```

核心产品：

> Web DApp。

核心入口：

> 免费 CA 安检。

核心传播：

> 风险报告卡片 + Telegram Bot + SEO/GEO + KOL/群主推广。

核心转化：

> 钱包体检 + 授权清理 + 深度报告 + 会员。

核心留存：

> 积分体系 + 安全贡献 + 推广奖励 + 周期性风险复查。

当前不做：

> 全自动交易拦截和浏览器插件核心版。

一句话结论：

> 这不是一个单纯的查币工具，也不是一个单纯的钱包清理工具，而是一个从“买前防坑”到“买后清理”的 Web3 安全操作入口。第一阶段要轻执行、重判断、重报告、重传播；先把“买币前先查 CA”打成用户心智，再逐步扩展到钱包体检、授权清理、粉尘归集和安全网络。
